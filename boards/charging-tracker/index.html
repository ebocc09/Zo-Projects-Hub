Environment

Which Garage instance the dashboard reads from. Each keeps its own sign-in, its own live-read cookie and its own vehicle list, so switching never mixes the two fleets or loses what you were watching.

Engineering runs at garage.dev.teslamotors.com and holds pre-production and engineering VINs that do not exist in production. It is a separate Bouncer registration, so it needs its own sign-in — and its own session cookie if you want live read there.
In engineering the dashboard turns yellow and the vehicle graphic becomes a Cybercab, so a screenshot is never ambiguous about which fleet it came from.

Live vitals

Real-time readings straight off the vehicle instead of Garage's cached snapshots. Configured separately for each environment — the cookie below belongs to Production.

Both environments are signed in on the Zo Projects Hub, which keeps them separate: signing in to Production says nothing about Engineering. One session there covers every board. Open the Hub
— — set on the Zo Projects Hub, like the sign-ins above, and read by every board.
Off — everything reads Garage's cached snapshots, which trail by 8–12 minutes while a car is charging and much longer once it is parked. This is how the dashboard has always worked.
On — every monitored vehicle is read in real time, so a completion is caught in seconds instead of minutes. One live read is ~140 KB, so a sweep of 100 vehicles moves roughly 14 MB; fine for the short lists this is normally used with, worth knowing before loading it up. Any live failure silently falls back to the cached path.
Latch detection depends on this. The "still plugged in" tag and its reminders read CP_proximity, which exists only in the live vitals dump — Garage's cached snapshots carry no charge-port columns at all. With live read off, the dashboard cannot tell whether a finished vehicle is still on the charger, and those alerts never fire. A sleeping vehicle also answers the live endpoint with a 408, so proximity goes unreadable until it wakes; reminders pause rather than repeat on a stale reading.
The session is your full Garage identity — it is stored in .garage.json on this machine only, never sent back to this page, and never committed. It expires on Garage's own schedule; when it does, live read switches itself off and says so, and one click above puts it back.

Maintenance

Housekeeping for this browser. Removing vehicles affects the current environment's list only.

Active Mode

Hands-off monitoring. Instead of entering VINs, the dashboard mirrors the main-TRT geofence: every refresh it scans TRT —, adds any vehicle that has arrived, and drops any it added once it leaves. Vehicles you add by hand are kept alongside and never auto-removed. The offsite TRT is never scanned.

Off
Turning it on plays a short intro and begins scanning immediately. The board is cleared both when it is turned on and when it is turned off, so nothing carries in and nothing is left standing afterwards. Active Mode is session-only — a page reload starts with it off, and drops the cars it had put on the list.
Locked on, and enforced by the server rather than by this page — no combination of the boxes above can reach a delivered car. Every category listed is an undelivered one.
On — auto-added cars only appear once they are charging or charge complete (including complete + latched); cars still awaiting data stay hidden until they report.
Off — every car in the geofence shows, awaiting-data included.
Vehicles you add by hand are always shown, regardless of this filter.
